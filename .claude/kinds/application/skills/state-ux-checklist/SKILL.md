# State and UX checklist

Used at `full` rigor. `docs/design/state-flow.md` and `docs/design/ux-flow.md`
together answer each question, or say why it does not apply.

1. State ownership: which component owns each piece of state?
2. Data flow: how does data move from source to screen and back?
3. Loading, empty and error states: what does each screen show in each?
4. Navigation: which screens exist, and how does the user move between them?
